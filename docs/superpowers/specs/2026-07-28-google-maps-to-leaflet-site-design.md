# 하루키 장소 아카이브 — 실제 지도 사이트 설계

## 배경

기존 `haruki_map.html`은 실제 지리 좌표를 쓰지 않는 추상적 SVG "개념도"(위경도를 격자에 옮긴 것일 뿐 해안선도 없음)였다. 사용자는 실제 지리 좌표에 기반한 진짜 지도로 바꾸고 싶어했다.

처음엔 Google Maps JavaScript API로 논의를 시작했으나, Google Cloud 결제수단 등록(선불 ₩40,000)이 필수라는 걸 확인한 뒤 사용자가 **완전 무료인 Leaflet.js + OpenStreetMap**으로 전환을 결정했다. API 키·결제수단 등록이 전혀 필요 없다.

## 목표

- 기존 종이·잉크 감성 디자인(CSS 변수, 라이트/다크 테마)과 필터·카드 UI 구조는 그대로 유지
- 지도 패널만 추상 SVG → 실제 지리 좌표 기반 Leaflet 지도로 교체
- `places.csv`를 런타임에 fetch해서 파싱 → 조사 세션에서 CSV를 갱신하면 재빌드 없이 사이트에 반영
- 새로운 필터 차원 2개 추가: 지역(권역), 작품(계층+검색)
- 지금도 실제 방문 가능한 식당·카페류는 마커 모양을 다르게 표시

## 데이터 스키마 변경

기존 13컬럼(`name,lat,lng,address,category,work,evidence,evidence_grade,source_url,status,my_note,key_location,source_type`)에 2개 추가:

- **`region`** — 큰 권역 태그: 간토(도쿄)/간사이(오사카·교토·고베·아시야)/홋카이도/규슈(후쿠오카)/도호쿠·기타혼슈/해외(그리스·하와이·핀란드·스코틀랜드 등). 기존 65건 전수에 좌표·주소 기준으로 소급 태깅 필요.
- **`poi_type`** — 지금도 실제로 영업 중인 식당·카페·바인 경우 값을 채움(예: `식당카페`), 아니면 공란. 폐업 확인된 곳(DUG 등)은 공란 유지. 기존 65건 전수 재검토 필요.

CLAUDE.md의 절대 규칙(좌표 추측 금지, 없는 출처 금지 등)은 이 스키마 확장에도 그대로 적용 — `region`은 이미 확보된 좌표/주소로 기계적으로 분류 가능하지만, `poi_type`은 "현재 영업 중" 여부라 애매한 항목은 ledger의 기존 evidence를 근거로만 판단하고, 불확실하면 공란으로 둔다.

## 아키텍처

- 정적 HTML/CSS/JS 한 파일 (`index.html`), GitHub Pages로 배포
  - 저장소: https://github.com/kzxoxc/haruki-map (public)
  - 배포 주소: https://kzxoxc.github.io/haruki-map/
- **Leaflet.js + OpenStreetMap 타일** (CDN 로드, API 키 불필요)
- **PapaParse**(CDN)로 `places.csv`를 런타임에 fetch + 파싱
- 기존 필터 칩 유지: 카테고리(A/B/C), source_type(소설/에세이·자전적/영화/팬덤헌정), evidence_grade(1/2/3), key_location(⭐만 보기)
- 신규 필터:
  - **지역 칩** (region 컬럼 기준)
  - **작품 필터** — 장편소설/단편집/에세이·논픽션 대분류 아래 개별 작품을 트리로, 검색창으로 이름 타이핑 필터도 가능. 기본은 전체 표시, 개별/전체 토글 가능. 대분류는 기존 `source_type`(소설/에세이·자전적/영화/팬덤헌정)을 기반으로 하되, "소설" 안에서 장편/단편집 구분은 `work` 컬럼 텍스트 패턴(예: "여자 없는 남자들 - 기노"처럼 " - "로 단편집명과 개별단편명이 이어진 경우 단편집으로 분류)으로 파싱
- 지도 마커: category별 색상(기존 인디고/모스/브라스 유지) + `poi_type=식당카페`는 별도 아이콘 모양(예: 원형 대신 컵 모양)
- 마커 클릭 ↔ 카드 클릭 상호 연동 (기존 SVG 버전의 동작 방식을 그대로 Leaflet 마커에 이식)

## 에러 처리

- `lat`/`lng`가 비어있는 항목(고치현·시나가와구·아오야마도리 등 구조적으로 점좌표 불가능한 6건)은 지도에 마커를 그리지 않지만, 카드 목록에는 그대로 표시(주소/텍스트 설명만)
- `places.csv` fetch 실패 시 사용자에게 에러 메시지를 화면에 표시(콘솔 에러만으로 끝내지 않음)
- CSV 파싱 후 각 행의 컬럼 수가 15개(기존 13 + region + poi_type)가 아니면 콘솔에 경고 로그(조용히 무시하지 않음)

## 테스트 계획

- 로컬에서 정적 서버(`python -m http.server` 등)로 열어 지도 렌더링·필터·마커-카드 연동 동작을 수동 확인
- 실제 GitHub Pages 배포 URL에서도 동일하게 확인 (로컬과 배포 환경의 CORS/경로 차이 체크)
- `region`/`poi_type` 태깅 후 65건 전수가 15컬럼 스키마에 맞는지 무결성 검사(필드 수 카운트)
- 좌표 없는 6건이 지도에서는 빠지고 카드 목록에는 남는지 확인
